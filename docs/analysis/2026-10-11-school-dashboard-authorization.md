# 教室管理ダッシュボードの応答全体の認可

`getOrganizationDashboardSnapshot` は学校管理者の業務画面だけが使う。生徒の一覧が担当範囲に限定されていても、同じ応答に含まれる担当変更履歴、講師一覧、教室全体の集計は講師へ返してはいけない。入口の `requireActiveOrganizationContext` へ `GROUP_ADMIN` を指定し、並列読み取りを始める前に応答全体を認可する。ストレージ登録の `INSTRUCTOR` は学校管理者のグローバル役割でもあるため、登録を削除せず組織役割の正本と最新 grant を入口で確認する。

一般講師と明示 grant の講師は、担当の有無にかかわらずこの直接 API が 403 となる。既存の担当生徒の進捗 API は維持する。学校管理者は固定教室の応答を取得でき、別教室の氏名・履歴を含めない。サービス管理者は別の全教室 API を使い、この単一教室 API へ迂回権限を追加しない。商用開通処理の内部呼び出しも、既存の学校管理者条件を満たす。

独立 clone の合成データで、修正前は直接 API の講師拒否 3 ケースが 200 を返すことを確認した。修正後は追加 10 unit と関連 51 unit、型チェックが成功した。正規担当講師・担当なし講師、正本 STUDENT の grant 講師、別クラス・別教室の生徒と担当変更履歴を用いて、拒否応答に氏名・履歴・集計がないことを検証する。保存済み actor の失効、version 更新、学校管理者 flag 除去、教室無効化も再認可して拒否する。

`node scripts/api-regression/organization-dashboard-permissions-native.mjs` は、migration の実テーブル定義と合成ユーザーだけを使った使い捨てローカル D1 へ、実 API router を直接呼び出す。113 checks が成功した。標準 API 回帰にも講師の直接拒否・全応答の別教室除外・失効後の拒否を追加した。最初の native 起動はインストール済み workerd より新しい互換日を指定して失敗し、ローカル fixture の互換日を対応済みの `2026-10-01` へ合わせた。失敗記録は保持している。

これは限定修正のローカル証拠であり、統合後の同一 SHA の正式全 gate と公開前の独立レビューは別に行う。本番 DB 操作、実本人の権限付与、実 AI、公開はこの修正担当から実行していない。
