# Writing activity jobの元提出への固定

PR57の [P2レビュー](https://github.com/wadansyaku/medace-english-app/pull/57#discussion_r4187132740) を修復したローカル候補。基準は `7d379eb65fa4d6904d7447ec45c91c35e161631b`。

従来のjobは課題IDと活動時刻だけを保持し、再試行で最新submissionの評価を検査していた。Aの同期失敗後にBが作成されると、Aの正当な記録がBによって拒否されたり、未確認Aの記録が実評価Bによって許可されたりする。

新しいjobは `writingSubmissionId` を必須保存し、dedupe keyにも提出IDを含める。提出受領・講師返却/再提出要求・課題完了のenqueueは、操作で確認した元提出IDを渡す。再試行はその提出の保存済みOCRと人手で選択された評価のみを検査し、課題・生徒・組織の一致も確認する。活動時刻は元payloadのままmission更新と東京日付のKPI再構築へ渡す。後続attemptの生成や評価は許可判断と日付を変えない。

## 旧payloadの互換限界

旧jobには提出IDもイベント種別（提出、講師返却、完了）もない。活動時刻はこれらの異なるイベントの時刻であり、提出時刻との一対一対応は保証されていない。同じミリ秒のイベントや、保存後に変わった/消えた提出の履歴も元payloadだけでは区別できない。現在残っている提出が1件、または時刻に一致する行が1件であっても、作成時の元提出を証明する識別子にはならない。

未完了の旧jobを最新submissionや時刻から自動補完しない。再試行時は `FAILED` とし、元提出識別子の欠落と講師の手動確認が必要な理由を `last_error` に保持する。jobとpayloadを削除・書換えしない。既にCOMPLETEDの旧jobは従来通り再実行しない。過去の成績、学習履歴、XP、SRS、既存KPIをこの修正で遡及変更しない。旧jobの個別修復は元提出の運用証拠を確認する別作業になる。

## 検証

実SQLiteの永続job経由で、A実評価の同期失敗→Bサンプル→A再試行成功、Aサンプル/処理元欠落→B実評価→A再試行拒否、元活動日の東京日付、成功済みjobの再送抑止、旧payloadのFAILED保持、課題/生徒/組織の不一致拒否、同時刻の別提出jobの非混同を確認。講師返却のcommit後再試行は元提出IDと返却時刻のまま回復する。対象3filesの73unitが成功した。

全体型チェックと `git diff --check` も成功。この担当はremote/API/build/browser/runtimeを操作していない。正規公開gateは統合担当の最終候補で継続する。
