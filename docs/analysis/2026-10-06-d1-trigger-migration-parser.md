# Provider budget migration remote parser repair

Candidate base: `d5724dc1b5c1463a39939d5a1e3a0164d4deaf9d` (PR 57). The first preview workflow failed while applying migration 0050 with REST `/query` error `incomplete input: SQLITE_ERROR` (7500), after 0049 succeeded. Root read-only inspection found 0050 absent from `d1_migrations` and zero `ai_provider_%` objects in `sqlite_master`, so the failed migration did not leave partial schema. Production was unchanged.

The original 0050 is valid native SQLite: Wrangler 4.145.0's `unstable_splitSqlQuery` produces 13 complete statements, and all execute locally. The same installed Wrangler reads each migration, appends its ledger INSERT and sends the complete string to the remote `/query` path. Local execution instead splits statements client-side. Thus passing local replay does not establish remote transport acceptance.

Cloudflare's repository contains reports of multiline trigger migrations failing on the remote path, including [#4998](https://github.com/cloudflare/workers-sdk/issues/4998) and [#15178](https://github.com/cloudflare/workers-sdk/issues/15178). A reporter documented a [single-line trigger workaround](https://github.com/cloudflare/workers-sdk/issues/4998#issuecomment-2051860036). Reports [#14991](https://github.com/cloudflare/workers-sdk/issues/14991) and [#15314](https://github.com/cloudflare/workers-sdk/issues/15314) concern CRLF and lowercase BEGIN, respectively; this candidate already has zero CR bytes and uppercase BEGIN. [#15690](https://github.com/cloudflare/workers-sdk/issues/15690) reports a similar failure with LF-only, uppercase-BEGIN multiline SQL. These reports support investigating the remote parser, but they do not prove the exact server-side mechanism for this application's failure.

The repair formats each of 0050's eight triggers as one physical line. It changes whitespace only, preserving every token, CASE expression, guard, reservation counter, settlement CAS effect, audit insertion and immutable-history rule. No previous migration or existing application table is changed. 0050 is a new, unregistered migration in the current release candidate; no already-applied production migration is rewritten.

The new test checks LF/uppercase-BEGIN/single-line boundaries and replays all 14 complete statements including Wrangler's ledger append in isolated native SQLite. The existing budget tests continue to verify concurrent admission, double settlement, unknown reservation retention, audit rollback and old-schema preservation. This test covers the installed client parser and local semantics; root's read-only remote EXPLAIN probes and the next preview migration gate must establish remote acceptance before production release.

No remote write, provider call, application build, deployment or production operation was performed by this repair subtask.

Local validation: 40/40 tests across the budget and migration parser suites passed, as did `tsc --noEmit` and `git diff --check`. Comparing whitespace-normalized 0050 content against the candidate base proved identical SQL content. Root's remote read-only `EXPLAIN CREATE TRIGGER` probes returned 7500 for both multiline and single-line forms; EXPLAIN can alter trigger detection, so that result neither proves nor disproves ordinary single-line CREATE acceptance. The preview gate remains the required next evidence.
